## The audit changes the safety picture — **read carefully**

`agent task a51ed9d0fd91ab977` (2026-05-07) ran a codebase audit looking for the same shape as the reconciliation auth bug. **17 findings, 7 HIGH severity.** Two systemic root causes:

### Root cause A: WS user channel is not connected to the orchestrator

`UserChannelClient` is only consumed in `clob_test/src/fill_tracker.rs` and `clob_test/src/bin/clob_test_helper.rs` (test harnesses). The running supervisor has **no consumer** of `UserEvent::Trade` events. As a result:

- **`update_trade_status` / `process_fill_event`** (`executor.rs:946, 1577`) — defined and tested, **zero production callers**. State machine never advances `Submitted → Matched → Confirmed`.
- **INC-021 phantom-payout reversal** (`executor.rs:1006` + `orchestrator.rs:1983-1993`) looks for `TradeStatus::Confirmed` — never set in live → fires unconditionally on every resolution.
- **INC-020 proactive-exit live path** (`orchestrator.rs:3517-3553`) polls `executor.sell_orders_for_position` for `terminal=true`. `is_terminal()` only returns true for `Confirmed/Failed/Cancelled` — none ever set. Loop always exits with `terminal=false, filled=0`. Logs "position holds, no bookkeeping update" and continues. Live exits silently never reconcile.
- **`RevertRateTracker`** (`circuit_breaker.rs` + `orchestrator.rs:3376`) records `FillOutcome::Reverted` but **never** records `FillOutcome::Confirmed` anywhere. `trip_signal` divides reverts by total — total = reverts only → rate is 100 % as soon as 10 reverts accrue.
- **B4.5 parallel fill confirmation** (`fill_confirmation.rs:180`) — entire module's public function has zero callers. CHANGELOG / ARCHITECTURE / ROADMAP all claim it's shipped.
- **B3.2 suspense subsystem** (`accounting.rs:591, 644, 689, 702`) — `enter_suspense`, `confirm_from_suspense`, `mark_suspense_retrying`, `reverse_suspense` all exercised only by unit tests. The "ghost-fill defence-in-depth" claim in `docs/POLYMARKET_ISSUE_WATCHLIST.md:59` is **false in production**.
- **`fill_quality::record_actual`** (`fill_quality.rs:115`) has zero callers. The whole intent-vs-actual point of the log is unrealisable until we have actual fill data.

These all collapse to a single missing wire: **the orchestrator needs a tokio task that consumes `UserChannelClient::next_event()` and dispatches each `UserEvent::Trade` to `executor.update_trade_status` and (where appropriate) `executor.process_fill_event` + `accounting.confirm_from_suspense` / `revert_tracker.record(...)`**.

### Root cause B: INC-020 was incompletely applied

The proactive-exit fix at `orchestrator.rs:3466` is correct. The **replacement** path at `orchestrator.rs:3033` was missed — still calls `engine.liquidate_position` unconditionally. With `max_concurrent > 1` and replacements firing on the cooldown timer (default 120 s), every replacement phantom-credits accounting (`current_capital += bid × shares`) while the wallet still holds the shares. **This is the reason `max_concurrent` is currently rolled back to 1.**

### Other HIGH-severity items

- **#5 `pm_open_count() > 0` gate** (`orchestrator.rs:1215, 1684, 1865, 1954, 2073`) — reconciliation, proactive-exit, postponement-check, API-resolution-poll all gated on PM having open positions. Orphan venue positions cannot be discovered when PM is empty. The Spurs YES + INC-D9 Draw-NO are both downstream consequences.

- **#6 `evaluate_arb_fills` unwired** — INC-D9 itself. The CB-trip safety net we shipped this session is the bridge until the full auto-unwind is wired (which depends on the WS user channel — see Root Cause A).

### MEDIUM-severity items

- **#8** Delete the dead `reconcile_startup` / `reconcile_periodic` no-auth wrappers in `lib.rs:1119, 1145`. They have zero callers post-fix, but they're a regression foothold for anyone using autocomplete.
- **#11** `execute_arb_batch` (B3.7 batch order submission) has zero callers. Either wire as default with sequential fallback (the documented behaviour), or delete and update CHANGELOG.
- **#12** `OrchestratorConfig` fields `mode`, `min_profit_ratio`, `postponement_rescore_days` are dead (build warnings). Operators tuning them in `config.yaml` see no effect.
- **#13** `position::update_leg_with_fill` (NT-1) — predecessor of `apply_exit_fills`, zero callers, delete.
